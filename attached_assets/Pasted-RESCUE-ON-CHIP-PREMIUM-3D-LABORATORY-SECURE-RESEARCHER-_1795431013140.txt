B3. Email verification for login

When a researcher signs in:

1. Enter their registered email.
2. Request a secure one-time login code.
3. Send the code to the researcher’s email.
4. Display a dedicated verification-code screen.
5. Verify the submitted code through the authentication provider.
6. Create a secure authenticated session only after successful verification.
7. Redirect the researcher to their personal dashboard.

Support:

* Expiring single-use codes.
* Resend-code controls with cooldown.
* Rate limiting.
* Invalid-code handling.
* Expired-code handling.
* Session expiration.
* Secure logout.
* Account recovery.

Do not generate or validate email codes using insecure frontend-only logic.

Do not log OTP codes or expose them to other users.

If email-password and email-OTP login are both offered, clearly separate the supported authentication flows and do not claim that email OTP is a second authentication factor unless that flow is actually implemented and independently enforced.
